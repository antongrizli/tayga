# Steering and GSO recovery implementation — 17 October 2026

Implementation starts from main `88876e2`. The detailed local handoff is
`improvenments/implementation-gap-and-recovery-plan-2026-10-17.md`; that directory
is intentionally Git-ignored. This maintained report records shipped behavior
and verification separately from historical claims in those local proposals.

## Changes

- **FIX-01:** groups and flows publish one permanent queue owner per bucket.
  Removed packet-size promotion; retained independent IPv4/IPv6 admission
  counters and consolidated packet header reads. Collisions share a queue and
  buckets do not expire. This prevents queue migration; byte balance and network
  ordering remain workload-dependent. BPF instruction emission is bounded.
- **FIX-02:** software TCP/UDP emitters reserve IDs from actual segment lengths,
  including empty payloads. Tests inspect emitted IDs, DF flags, payload,
  checksums, sequences and allocator advancement across wrap and scalar use.
- **FIX-03:** a contiguous short TCP tail carries a pseudo-header seed and
  NEEDS_CSUM metadata when vnet checksum offload is negotiated. The no-vnet path
  retains software checksums. Tests cover 0/10/12-byte framing and TCP options;
  a source-linked kernel fixture checks completed packets on a veth receiver.
- **FIX-04:** explicit groups/flows direct tests, concurrent admission, size
  changes under unread backlog, collisions, queue limits, descriptor pressure,
  churn and lifecycle/fallback checks. CI and the system runner exercise both
  eBPF modes independently of userspace flow dispatch.
- **FIX-05:** raw-client/synchronized-status acceptance, historical reference
  floors, source identities, failed-run retention and five alternating paired
  trials. Data-port schedules are reproducible within each pair, with separate
  ranges for warmup/upload. See [benchmark instructions](../../bench/README.md).
- **FIX-06:** production startup creates persistent TUNs only for kernel policy.
  Modern steering studies select the production configuration rather than
  slicing shell conditionals. Integrity tests can use unmodified startup.
  CLI help/man pages describe flows and its actual guarantees.
- **FIX-07:** host/subnet mapping admission/reload invariants are covered without
  rejecting valid IPv4 overrides. Public software GSO functions enforce matching
  family/type/MSS/length metadata; TCP full-checksum fallback remains supported.
- **Additional recovery fix:** single-segment TCP output clears GSO type/size
  while retaining checksum offload. This applies to split heads and the unified
  paths in both translation directions. Multi-segment output remains aggregated.
- **Benchmark reliability:** scheduled data/warmup ports are reserved from
  ephemeral allocation in the disposable client namespace. This prevents an
  iperf control connection from taking a data port before its explicit bind.
  Existing reservations are preserved and the effective list is retained.
  A Linux socket regression keeps four controls open while all eight explicitly
  bound data streams connect successfully in a deliberately narrow port range.

Additional dormant-lease hold/rate limiting and async multi-SQE/SPSC work remain
**deferred**, as explicitly optional in the handoff. Existing minimum lease aging
is retained. No new promotion mode, map eviction or unproven drain protocol was
introduced.

## Performance acceptance

### Confirmed GSO output defect

Kernel drop tracing identified `validate_xmit_skb()` discards after
`__skb_gso_segment()` / `tcp_gso_segment()` returned `-EINVAL`; checksum offload
and linearization probes did not report failures. A rejected IPv4 packet had
1,428 payload bytes, MSS 1,428, a 32-byte TCP header with timestamps, and GSO
metadata still enabled. A single packet must be submitted without segmentation
metadata, even when its input was marked GSO.

The original wire fixture used 20-byte TCP headers and two full segments, which
missed this combination. The expanded fixture covers 20/32/60-byte TCP headers,
one/two full segments, odd/even tails and an exact 1,260-byte IPv4 tail. Before
the fix, all 36 writes appeared successful but only **39 of 45** expected wire
packets arrived: the six one-segment heads with TCP options disappeared. After
the fix, **45 of 45** arrived with valid checksums, payload, sequence numbers,
DF and CWR/FIN/PSH flags. Native units and ASan/UBSan also pass the expanded
split tests and both-direction empty/short/exact-MSS/multiple-segment metadata
tests. This is a reproduced forwarding fix, not a throughput acceptance claim.

Diagnostic guest evidence is in `/tmp/recovery-gso-metadata-v14b/` and
`/tmp/recovery-options-head-{before-corrected,after}/`. These traces are
instrumented diagnostics and must not be pooled with capacity trials. Prior
NAPI, admission, affinity, RPS and backlog experiments did not pass acceptance;
their experimental code and configuration changes are not enabled in the
working-tree defaults.

## Controlled follow-up — 18 October 2026

Starting from main `093be603f300964858b9f2dedc3e7e14edbb76c9`, the recovery
runner now freezes the harness independently of daemon sources, records explicit
experiment/pair/arm identities, pairs by those identities and checks harness
archive hashes. Same-policy comparisons have an explicit diagnostic purpose;
valid diagnostics never imply product acceptance. macOS sessions capture power
source/settings before and after each run and reject transitions or mismatched
arms. An optional `ENDPOINT_AFFINITY=per-client` records and verifies actual
endpoint CPU masks; the default remains `off`.

The only production C change in this follow-up exports four already-maintained
per-worker byte counters. It does not alter admission or packet processing.
Packet-path candidates remain isolated under the ignored
`build/recovery-20261018/sources/` directory pending acceptance.

Five AC-controlled original/kernel versus main/kernel pairs yielded medians of
73.795/72.452 versus 73.765/71.728 Gbps (download/upload). The data do not establish
a persistent 17–25% source-induced slowdown or statistical equivalence: ranges
are wide, and original download still has interface drops. Five pairs of one
current build with kernel versus flows failed the original throughput,
retransmission and worker-share gates.

A real BPF test demonstrates an admission limitation without bucket collisions:
interleaved control/data connections can assign four bulk flows to only two of
three queues. Actual tuple traces also show separate data/ACK worker placement.
An isolated TCP reply-hint candidate preserving permanent primary owners raised
both medians from 74.664/77.357 to 92.139/91.175 Gbps versus current flows, with
five positive pairs in both directions (one-sided sign-test p=0.03125). However,
upload retransmissions per sent GB increased from 7.936 to 15.496. **This candidate
is not accepted or enabled.** Worker pinning alone also failed acceptance.

A separate sequence observer finds forward gaps before translation, including
with stationary workers and CPU-pinned endpoints. This establishes upstream
sequence discontinuities, not their complete cause or the fraction of all
retransmissions attributable to them. Instrumented probes are not capacity
samples. Hierarchical admission and TUN NAPI were evaluated only in isolated sources;
no acceptance thresholds or historical floors have been relaxed.

Detailed local evidence, all failed studies and remaining barriers are recorded
in `improvenments/throughput-recovery-execution-report-2026-10-18.md` and
`build/recovery-20261018/`. Raw sessions remain under
`~/.local/state/tayga/perf-sessions/`. The first two studies lack exact timing of
the battery-to-AC transition and are excluded from final causal attribution.

The final five-pair hierarchical/reply-hint/NAPI study also **failed**. Candidate
medians were 87.160/88.393 Gbps versus kernel 88.685/72.704: download decreased
1.72%. Sign-test p values were 0.5/0.1875; upload retransmissions/sent GB rose
6.183 to 21.406. All measured quality gates passed, which does not override
performance failures. This packet-path candidate was rejected.

The isolated source passed kernel/system checks, production startup integrity
and PMTUD for all three policies, native units, CI-mode ASan/UBSan, targeted
mapping leak checks and WITH_URING runtime units. Integration exposed two old
protocol-oracle defects reproduced on main: Scapy Raw-layer selection did not
consistently identify application payload, and a small MPTCP SYN incorrectly
expected DF=1/ID=0. Wire-header-based payload selection and the existing small
packet DF/ID rule now give 62/62 protocol cases. Initial failures are retained.
The updated portable suite passes 159 tests (21 skips); Linux tools pass 160
(one skip as root). All seven installed guest artifacts were restored and
compared with their backups; no test namespaces, daemon processes or kprobes
remain. Detailed acceptance and remaining actions are in the local report.
