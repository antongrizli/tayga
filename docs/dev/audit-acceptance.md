Статус: **подготовлено, не запускалось**. Все сценарии ниже ожидают выполнения.
Syntax-only проверка компилятором не заменяет эти сценарии. Команды в этом
документе предназначены для последующего запуска на выделенном стенде.

## Среда и артефакты

Linux: отдельная VM с systemd, TUN, network namespaces, Scapy, iproute2,
Unbound и поддержкой io_uring для соответствующей части матрицы.
FreeBSD: отдельная VM с rc.d, TUN, epair, PF для managed-профиля и генератором RA
на втором конце epair. Linux netns-сценарии на FreeBSD не переносимы напрямую.
Проверять raw ICMPv6 с правами root; отсутствие прав проверять отдельным случаем.

Зафиксировать архив исходников со всеми незакоммиченными изменениями, его SHA256,
хэши обоих бинарников, флаги компилятора, версию ОС/ядра и начальную конфигурацию.
Одного git HEAD недостаточно для идентификации текущего кандидата.
Для каждого случая сохранять stdout/stderr, exit status, монотонные отметки времени,
JSON статистики и, где применимо, pcap, PID/PPID, список интерфейсов/маршрутов до и после.
Результат: `pending`, `pass`, `fail` или `blocked` с причиной. SKIP не считается PASS.
Выходные каталоги должны быть новыми; артефакты предыдущего запуска не перезаписывать.

## RA-supervisor: новые сценарии для стенда

Использовать два изолированных сетевых узла и реальные RAs, не подменяя результат
helper shell-скриптом. Генератор должен посылать также unsolicited RAs: supervisor
после первого RS продолжает слушать постоянный сокет. Для быстрой матрицы взять
lifetime 8 и 16 секунд (допустимая единица RFC 8781 — 8 секунд).
Дочерний процесс сначала заменить foreground fixture, который пишет конфигурацию,
PID, время старта и полученные сигналы в журнал; затем повторить с настоящим TAYGA.
`test/system/test_ra_supervisor.py` содержит генератор реальных RA и foreground
fixture: продление, смена префикса, USR2, чужой отзыв, отзыв активного префикса,
expiry, cleanup снимка и порядок NAT66 controller/rollback через fake controller.
Последнее подтверждает orchestration, но не работу реального firewall. Остальные случаи таблицы и запуск с настоящим TAYGA
остаются отдельной приёмкой. Fixture подключён к review-gates, но не запускался.

| ID | Действие | Критерий приёмки |
|---|---|---|
| RA-01 | Конфиг без RA metadata | Helper заменяется командой через exec; дополнительного supervisor нет |
| RA-02 | Передать валидный PREF64 A | Один дочерний процесс; его снимок содержит A; исходный конфиг побайтно сохранён |
| RA-03 | Повторить A до истечения lifetime | Дедлайн продлён от нового RA; PID ребёнка не меняется |
| RA-04 | После A прекратить RA | По истечении lifetime начинается остановка; ребёнок завершён не позднее чем через 6 с; supervisor возвращает ошибку |
| RA-05 | Передать A с lifetime=0 | Остановка начинается после получения отзыва, без ожидания прежнего дедлайна |
| RA-06 | Передать положительный PREF64 B | Старый ребёнок остановлен и reaped до запуска нового; новый снимок содержит B; одновременно работает не более одного ребёнка |
| RA-07 | Повторить ту же сеть в эквивалентной записи IPv6 | Двоично равный префикс не вызывает перезапуск |
| RA-08 | Передать RA с hlim!=255, нелокальным src или с другого интерфейса | Префикс и дедлайн не обновляются; незаконное RA не продлевает работу |
| RA-09 | Передать PLC 0..5; отдельно 6/7, неверную Length, усечённое RA | Допустимые варианты распознаны; остальные не принимаются как новый префикс |
| RA-10 | Передать чужой отзыв; несколько PREF64 в одном RA | Чужой отзыв не останавливает действующий префикс; выбор нескольких вариантов документирован, без циклических рестартов |
| RA-11 | Отправить HUP/USR2 supervisor | Сигнал получает только принадлежащий ему ребёнок; USR2 публикует свежую статистику |
| RA-12 | TERM/INT supervisor; отдельно авария ребёнка | Нет orphan-процессов; снимок удалён; корректный код выхода для внешней политики restart |
| RA-13 | Нет CAP_NET_RAW, отсутствует интерфейс, нет прав на каталог снимка | Понятная ошибка и ненулевой выход; ребёнок не запускается с просроченным/неподтверждённым префиксом |
| RA-14 | Ошибка exec, чтения конфига или записи снимка | Нет второго ребёнка/утечки fd; исходный конфиг сохранён; ошибка видна в журнале |
| RA-15 | NAT66: A→B с controller; ошибка up B; отдельно запуск без controller | Старый child остановлен до down/up; новый запускается только после настройки B. При ошибке восстанавливается сеть сохранённого профиля, без запуска старого translator. Без controller несовпадение префикса останавливает supervisor |

При остановке после expiry/withdrawal отдельно измерять начало остановки и её
завершение: graceful drain ограничен, но не обязан завершаться мгновенно.
Проверить 20 последовательных обновлений/смен префикса: fd и число процессов
не растут. После SIGKILL supervisor отдельно учитывать оставшиеся снимки и
поведение cleanup службы; graceful cleanup не доказывает cleanup при SIGKILL.

## Службы и платформы

| ID | Матрица | Критерий приёмки |
|---|---|---|
| SVC-01 | Linux systemd, manual и RA-профиль | С реальными prepare/up/verify helper-скриптами старт доходит до active; READY приходит от корректного процесса |
| SVC-02 | chroot + непривилегированный пользователь; файловый NOTIFY_SOCKET вне chroot | Сокет подготовлен до изоляции, READY доставлен; запуск не зависает до TimeoutStartSec |
| SVC-03 | stdout/syslog/journal | READY не зависит от выбранного способа логирования |
| SVC-04 | SIGSEGV ребёнка, supervisor; серия аварий | Restart=on-failure и StartLimit срабатывают; после stop нет дочернего процесса, принадлежащего профилю TUN или DNS sidecar |
| SVC-05 | Linux OpenRC manual/RA | Background PID принадлежит ожидаемому процессу; stop завершает всё дерево до сетевого cleanup |
| SVC-06 | FreeBSD rc.d manual/RA | daemon pidfile и procname совпадают с фактическим процессом; start/status/stop/restart работают; PID не остаётся после stop |
| SVC-07 | Ошибка verify после старта | Откат реального профиля восстанавливает маршруты, DNS и firewall; чужие объекты не затрагиваются |
| SVC-08 | Reconfigure RA-профиля | Режим auto сохранён; заново определяется интерфейс/префикс; нельзя молча превратить профиль в manual |

Матрицу SVC выполнять на одноразовой VM с реально установленным кандидатом.
Заглушки ExecStartPre/ExecStartPost не закрывают приёмку установщика.

## DNS64, лимитер и статистика

| ID | Действие | Критерий приёмки |
|---|---|---|
| DNS-01 | /32,/40,/48,/56,/64,/96 через helper и managed Unbound | AAAA содержит IPv4 в позиции RFC 6052; prepare, readiness и HTTP verify используют тот же префикс |
| DNS-02 | CD=0/1; DO=0/1; OPT больше 64 байт, включая padding | A-запрос сохраняет CD, размер UDP и полный корректный OPT в пределах принятого буфера |
| DNS-03 | OPT после другой RR; усечённый RDLENGTH, duplicate OPT | Нет OOB/падения; валидный OPT найден; недопустимый ввод не становится повреждённым upstream-запросом |
| DNS-04 | EINTR, короткие чтения и ошибка открытия/чтения entropy | Успех только после получения всех байтов; при недоступной энтропии DNS discovery завершается ошибкой без fallback из времени/PID |
| RL-01 | rate=1,10,1000 после reset | Начальная ёмкость min(rate,200); дополнительного немедленного refill от нулевой метки нет |
| RL-02 | Контролируемое время, rate=3, дробные интервалы, длительный idle | Сохраняется дробный кредит; за интервал dt число разрешений не выше burst+floor(rate*dt); idle не удваивает burst |
| RL-03 | Параллельный flood, отдельный PMTU-поток, unlimited | Нет превышения общего бюджета/гонок; PMTU имеет отдельный бюджет; unlimited не отбрасывается лимитером |
| TX-01 | Успешный/неуспешный originated ICMP, sync | icmp_sent растёт только при успехе; ошибка TX не становится вторым dropped input |
| TX-02 | io_uring: enqueue, успешный CQE, ошибочный CQE, cancel | Enqueue ещё не icmp_sent; успешный CQE увеличивает один раз; ошибка/cancel увеличивает tx_failed один раз |
| TX-03 | Software GSO: отказ на первом и промежуточном сегменте | Успешные сегменты учтены; остаток агрегата не дублируется в drop; исходящий failed frame учтён один раз |

Для RL-02 добавлен `unit_icmp_rate_limit`: accounting принимает явное
монотонное время, проверяются burst, дробное пополнение и длительный idle
без sleep. Unit подключён к make test, но не запускался. Для TX-02 нужен действительный completion path или
детерминированная подмена CQE; проверка только enqueue недостаточна.
Инвариант rx=(tx−icmp_sent)+drops+self применять к scalar one-input/one-output
сценариям. Для GSO и фрагментации сверять отдельно входные агрегаты, выходные
кадры и байты; общий пакетный инвариант там неприменим.

## Persistence и критерий завершения

| ID | Действие | Критерий приёмки |
|---|---|---|
| DB-01 | Сохранить и перечитать аренды; старый tmp с правами 0644 | Новый файл имеет 0600, старый tmp не переиспользуется; возраст аренды сохранён в пределах точности секунд |
| DB-02 | Ошибки записи, fflush, file fsync, rename, directory open/fsync | Возвращается ошибка и сохраняется pending для повтора; доступна полная старая либо новая база, без усечённой опубликованной базы |
| DB-03 | Завершение процесса между write/fsync/rename/dir fsync | Зафиксировать результат каждой точки; успешный return допускается только после синхронизации файла и каталога |
| DB-04 | Скачок wall clock во время работы | Runtime lease/cache ageing остаётся монотонным; отдельно проверить wall-epoch преобразование при последующем сохранении и рестарте |

DB-03 с kill процесса подтверждает атомарность, но не моделирует потерю питания
и сброс дисковых кэшей; утверждение о power-loss durability требует отдельного
стенда с контролируемым storage fault. Ошибка fsync каталога после rename может
оставить уже новую базу: ожидается повтор сохранения, а не обещание rollback rename.

Приёмка закрывается только отчётом с артефактами обязательных случаев и причинами
blocked. До этого текущий статус — реализовано/статически проверено, runtime pending.
Производительность PR-8/PR-9/PR-10 оценивается после корректности отдельным A/B
прогоном; улучшение PPS или retransmits/GB по этому документу не заявляется.
